# OPS Bot Manager для Windows

## Запуск

1. Откройте папку `dist\onedir\OPS Bot`. При переносе на другой компьютер сохраните вместе `OPS Bot.exe` и папку `_internal`.
2. Для нового развёртывания разместите `.env` рядом с EXE. Используйте `.env.example` как шаблон. Для существующего проекта укажите его каталог в файле `ops-bot-home.txt` рядом с EXE. В файле должна быть одна строка с путём к каталогу, например `C:\OPS\ops-bot`. Сборка с `-UseProjectData` записывает путь к текущему проекту автоматически.
3. Дважды щёлкните `OPS Bot.exe`. При корректной конфигурации Manager автоматически запустит бота.

Кнопка **X** скрывает окно. Двойной щелчок по значку в трее возвращает окно. Правый щелчок открывает меню **Open**, **Start Bot**, **Stop Bot**, **Restart Bot** и **Exit**. Для завершения бота и Manager выберите **Exit**. Если значок скрыт Windows, откройте список скрытых значков на панели задач.

## Конфигурация и доступ

Manager использует `.env.local`, `.env` и переменные окружения в прежнем порядке приоритетов. `.env` перекрывает `.env.local`, а переменные окружения перекрывают оба файла. Относительные значения `DATABASE_PATH` и `LOG_DIR` вычисляются от каталога конфигурации. Значения по умолчанию — `data\agent.db` и `logs`. После правки `.env` нажмите **Restart**.

**Authorized Users** показывает допущенных пользователей и администраторов. **Add** даёт доступ по Telegram ID. **Revoke Access** отзывает доступ после подтверждения. Бот читает изменения из существующей базы SQLite при следующем запросе пользователя. История и другие записи сохраняются. Роль администратора задаётся через `TELEGRAM_ADMIN_IDS` в `.env` или соответствующей переменной окружения.

**Open Logs** открывает каталог журналов. `manager.log` хранит события запуска и остановки, `agent.log` — события бота. Оба журнала ротируются. Перед обновлением завершите Manager через **Exit**. Замените файлы сборки и сохраните внешний каталог данных или лежащие рядом `.env`, `ops-bot-home.txt`, `data` и `logs`.

## Сборка

В PowerShell из корня проекта используйте существующую `.venv` на Python 3.12 или создайте её командой `python -m venv .venv`.

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-windows.txt
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_windows.ps1 -UseProjectData
```

Стандартная сборка — `dist\onedir\OPS Bot\OPS Bot.exe`. Ключ `-OneFile` создаёт `dist\onefile\OPS Bot.exe`. Для передачи на другой компьютер возьмите только EXE и, для onedir, папку `_internal`. Конфигурация, ключи и база хранятся во внешних файлах. На компьютере, где запускается сборка, отдельный Python не требуется.

Для запуска Manager из исходников используйте `.\.venv\Scripts\pythonw.exe .\ops_manager.py`. Запуск `main.py` из консоли также доступен. Одновременный polling одного Telegram-бота на этом компьютере блокируется Windows. Если тот же бот уже работает на другой машине, Manager покажет конфликт от Telegram.

## Устройство запуска

PySide6 управляет окном, треем и асинхронным запуском отдельного процесса из того же EXE. Процесс бота использует существующий `main.run`, настройки и обработчики Telegram. Закрытие служебного канала останавливает polling и завершает приложение Telegram. Windows Job Object завершает дерево процессов при аварийном закрытии Manager или при превышении таймаута остановки. После ошибки запуск можно повторить кнопкой **Start**.
